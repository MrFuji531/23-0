What’s behind 23-0,
and how Full Side works.

A working independent interpretation of the promised 22-player mode, with a reproducible player database and an openly explained scoring model.

What I could verify

The live 23-0 home page offers a playable Classic mode and a disabled Full Side button. The Full Side description explicitly promises a 22-player team. There is no release date visible. I cannot establish why it has not launched or how long the current implementation has been in place.

Classic is a five-player draft: DEF, MID, RUC, FWD and utility. It draws a club and a decade, gives limited club/era rerolls, and scores a season when the lineup is complete. The official rules explain that ratings use statistics and honours relative to era baselines, spanning the 1990s onward.

The browser bundle examined was build 7e88b97. Its delivered game implementation supports five picks. Full Side is a disabled mode card; I did not find a hidden playable 22-player route in this bundle. That says nothing about unpublished work on the author’s computer or server.

Their player database

The downloaded catalogue contains 3,391 records covering 2,210 distinct player IDs, four decades and 19 club labels. A record represents one player at one club in one decade, rather than an entire career. The payload declares a 30-game threshold.

Fields include games, average disposals, goals, marks, tackles, hitouts, kicks and handballs; some later-era records also contain contested possessions, clearances, inside 50s, rebounds and other measures. It includes Brownlow votes, All-Australian and captain flags, finals played/won, inferred position information and decade baselines.

The frontend groups records by club and era and orders candidates using their fantasy average. Its draw code favours unused eras and excludes already-selected clubs in Classic. It also tries to offer players suitable for open positions. That restriction cannot carry over unchanged to 22 picks: there are fewer distinct clubs than roster spots.

Unknown: the original collection pipeline, upstream provider, exact positional inference, honour aggregation rules, scoring weights and final win thresholds. The fields are compatible with a statistical aggregation pipeline, but that is an inference—not proof that the author used fitzRoy, AFL Tables or any other specific source. Exact replication of the hidden scoring formula is not supported by the evidence.

The database actually used here

2,110 distinct players · 3,233 player–club–era records · 20 historical/current club labels. Built from 310,402 match-player rows dated from 1990 onward. The source cache’s latest match is 26 September 2026; this is a fixed snapshot, not an automatically updating feed.

  1. Read the AFL Tables Parquet cache.
  2. Resolve missing player IDs only where first name and surname match a single known player ID in the 1990-onward source records. This resolves 150 rows; 21 ambiguous rows are excluded rather than merged. The exclusions can slightly undercount affected players.
  3. Keep seasons from 1990, and group by player ID, club and decade.
  4. Normalise Footscray to Western Bulldogs and Kangaroos to North Melbourne before aggregation. Preserve Fitzroy and Brisbane Bears as distinct historical clubs.
  5. Keep groups with at least 30 appearances. Compute per-game statistics and Brownlow-vote totals within that club and era.
  6. Keep missing statistics as null, rather than assuming zero. Store player-source URLs and a source-file SHA-256 for reproducibility.
  7. Generate compact JSON and independent ratings, shipped with the game. Browsers do not call either original game’s API or the data sources.

Coverage is the downloaded cache, not a claim that every historical record is error-free. Players with fewer than 30 appearances in a club–decade are intentionally excluded. Players with the same name are distinguished by source ID; the same person across eras and clubs can only be drafted once.

Scoring: deliberately open

The game ranks every available statistic against player–club records in the same decade. Ties receive a midpoint percentile. This reduces some era differences, but is not a professionally validated cross-era model.

RoleStat weights
DEF40% rebounds, 25% one-percenters, 20% marks, 15% disposals
MID55% disposals, 25% clearances, 20% tackles
RUC75% hitouts, 15% disposals, 10% marks
FWD75% goals, 15% marks, 10% tackles
INTThe player’s highest role rating

When a metric is missing, the other weights are proportionally renormalised. The rating is 35 + 60 × weighted percentile + experience bonus + Brownlow bonus. Experience contributes up to 3 points at 100 games in that club–era. Votes contribute up to 2 points at 0.65 votes per appearance. Ratings therefore span approximately 35–100.

The team rating is a weighted average: each of the 18 starting players has weight 1, and each interchange player has weight 0.65. The 23 fictional opposition thresholds are 55, 56.75, 58.5, and so on up to 93.5. Your side wins a match when its unrounded rating meets the threshold. The displayed match order is fixed and shuffled. There are no random match outcomes or real-club fixture claims.

Limitations: statistical positional labels are estimates; defensive impact is poorly measured by the available box scores, particularly in older eras; advanced metrics can cover only part of a decade; 2020 shortened games are not individually time-normalised; averaging includes late-career and substitute appearances; peak seasons, All-Australian honours, captaincy, premiership contributions, chemistry and opposition adjustments are not modelled. Brownlow votes favour midfielders. These are reasons to treat the result as a game, not a definitive ranking of footballers.

Assignment is intentionally unrestricted: users can place a player wherever they like while seeing the role-specific rating. It avoids pretending inferred position labels are official eligibility rules. Later improvements should introduce verified season-level positions and better defensive measures before adding complexity to the season simulator.

What changes in the 22-player version

  • Six defenders, five midfielders, one ruck, six forwards and four interchange players.
  • Three club rerolls and three era rerolls across the entire draft. A reroll with no alternative is not consumed.
  • Clubs can recur, but a player cannot. Regular draws favour the least-used decades so every era gets represented.
  • Player search, ratings by role, free positional rearrangement, and a source record for every player.
  • Device-local draft recovery, seeded challenge links, completed-lineup links and a 23-round result display.
  • Shared lineups are embedded in the URL and can be modified by their owner; this is casual play with no authoritative leaderboard or anti-cheat claim.

The current version is static and can run from any ordinary web host. No accounts, paid data provider, server database or live API dependency are required. Snapshot refreshes use the included Python script. A trusted competitive leaderboard would require server-side validation and durable storage; that is outside this version.

Verification

The engine suite checks 100 complete seeded drafts, reproducible results, all 22 positions, era coverage, reroll constraints, invalid assignments, swaps, save restoration and duplicate-player prevention. It also verifies that every catalogue record has source provenance and finite ratings. Browser checks cover drafting, rearrangement, reload recovery, completing a season, sharing and responsive layout.

The original site was inspected through its public page, published instructions, page HTML, directly referenced JavaScript and public player data. The independent game engine was written from scratch. The interface was subsequently restyled to closely match 23-0 at the user’s request, including its displayed logo.
